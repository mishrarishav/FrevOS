DevSetu - connect this Windows computer

1. Extract the ZIP completely. Open Setup.cmd from the extracted folder.
2. The setup page opens in your browser. Enter the DevSetu server URL. Keep
   your VPN connected. No administrator username or password is needed here.
3. If you used Request to join on the login screen, wait for manual admin
   approval there. Enter that approved join code in setup and keep the same
   file activity choice that was reviewed. Connect this computer; no second
   approval or account password is needed in the installer.
   Alternatively an administrator can register a computer directly: optionally
   enable file activity, then click Connect this computer. A short
   code appears. On your own logged-in DevSetu browser (on this computer or
   another computer), open Discovery > Approve connection. An administrator
   selects the assigned user, checks the computer name and access, then approves.
4. Wait for Connected and reporting health. Open Discovery to view your laptop.
   You can close the setup window after that; the connector runs in the background
   for your Windows user and starts again when you sign in.

System monitoring does not require Git, a project, or an empty code folder.
It reports CPU, RAM, operating system and drive space. Optional file activity
collects bounded metadata from readable local drives with configured exclusions.
It does not automatically upload file contents. An explicit file-content request
opens a separate local approval page for that exact file once (UTF-8, at most
8 KiB, sensitive paths excluded and secret lines masked). Declining or expiry
does not read the file. Comparisons need earlier retained approved snapshots;
notifications cannot reconstruct earlier file contents.

Projects are added separately in DevSetu. Use Setup-Project.cmd only when you
explicitly want to bind this computer to a configured project Git checkout.
Existing files do not need to be deleted or moved for system monitoring.

If connection fails, the page shows its stage and a safe error code. Correct the
VPN/account issue and use Retry connection. Keep the launcher open during setup.
After a successful installation, reopening Setup.cmd reuses its protected
connection without asking for the administrator password. Setup-Account.cmd
keeps the older account-login setup for explicit compatibility use.

Updating an already paired system: download the current ZIP from your trusted
DevSetu server, extract it and open its Setup.cmd. Click Connect this computer
with the saved server. Setup verifies and updates only this user's existing
connector, preserving its device identity, credential, task and monitoring data.
No uninstall, account password or new pairing approval is required. The previous
runtime is kept privately for recovery (at most three update staging copies;
further updates fail closed rather than growing recovery storage indefinitely).
This is an explicit local update; existing versions do not update themselves.
The updated collector bounds pending work and reserves separate activity quotas;
server segments/summaries already work with older connectors. Read-only text
requests and connector-specific RAM metrics require the updated collector.

Paired-computer login requires the updated connector running on that computer.
With the configured HTTP flow, enter your own username/password in DevSetu,
choose Verify for this computer and confirm on its local connector page. Keep the
same browser; DevSetu checks both browser and connector proof before signing in.
A normal user sees only their own Discovery
systems. Administrators can sign in from other computers and review requests.
Do not disable certificate checks or browser local-network security.

Linux x64: extract the Linux archive and run ./install.sh as your desktop user
(not root). It opens the same system setup without Git or a project. A working
user systemd manager and cgroup v2 are required. Desktop notifications are not
offered by this Linux setup. ./install.sh --project keeps explicit project setup.
