DevSetu - connect this Windows computer

1. Extract the ZIP completely. Open Setup.cmd from the extracted folder.
2. Enter the DevSetu server URL and select your own existing account or Create
   my account. Enter YOUR username/password and choose monitoring consent.
   Use the full address of your DevSetu entry, including its path when present.
   A public HTTPS entry needs Internet access; a private entry may require VPN.
   No administrator password, project or Git is required.
3. Click Request access. An administrator sees your account AND computer in
   Discovery > Join requests, the notification bell and dashboard. When they
   approve, this same connector connects automatically. No code to copy.
4. Wait for Connected. Open Discovery and sign in with your own account, then
   use Verify this computer in the same browser. Monitoring keeps running
   after you close setup. A DevSetu Connection Status desktop shortcut shows
   fresh connection health, or Offline when the connector/network is unavailable.

Older browser requests and explicit administration:
   Select Advanced: update existing connection / legacy code. An older
   approved join code can still be entered with its reviewed activity choice.
   Alternatively an administrator can register a computer directly: optionally
   enable file activity, then click Connect this computer. A short
   code appears. On your own logged-in DevSetu browser (on this computer or
   another computer), open Discovery > Approve connection. An administrator
   selects the assigned user, checks the computer name and access, then approves.
   Wait for Connected and reporting health. Open Discovery to view your laptop.
   You can close the setup window after that; the connector runs in the background
   for your Windows user and starts again when you sign in.

System monitoring does not require Git, a project, or an empty code folder.
It reports CPU, RAM, operating system and drive space. Optional file activity
collects bounded metadata from readable local drives with configured exclusions.
It does not automatically upload file contents. An explicit file-content request
opens a separate local approval page for that exact file once (UTF-8, at most
8 KiB, sensitive paths excluded and secret lines masked). Declining or expiry
does not read the file. Comparisons need earlier retained approved snapshots;
notifications cannot reconstruct earlier file contents.

Projects are added separately in DevSetu. Use Setup-Project.cmd only when you
explicitly want to bind this computer to a configured project Git checkout.
Existing files do not need to be deleted or moved for system monitoring.

If connection fails, the page shows its stage and a safe error code. Correct the
network/account issue and use Retry connection. Keep the launcher open during setup.
After a successful installation, reopening Setup.cmd reuses its protected
connection in Advanced update mode without asking for an administrator password. Setup-Account.cmd
keeps the older account-login setup for explicit compatibility use.

Updating an already paired system: download the current ZIP from your trusted
DevSetu server, extract it and open its Setup.cmd. Select Advanced update mode and click Connect this computer
with the saved server. Setup verifies and updates only this user's existing
connector, preserving its device identity, credential, task and monitoring data.
No uninstall, account password or new pairing approval is required. The previous
runtime is kept privately for recovery (at most three update staging copies;
further updates fail closed rather than growing recovery storage indefinitely).
This is an explicit local update; existing versions do not update themselves.
The updated collector bounds pending work and reserves separate activity quotas;
server segments/summaries already work with older connectors. Read-only text
requests and connector-specific RAM metrics require the updated collector.

Paired-computer login requires the updated connector running on that computer.
With the configured HTTP flow, enter your own username/password in DevSetu,
choose Verify for this computer and confirm on its local connector page. Keep the
same browser; DevSetu checks both browser and connector proof before signing in.
A normal user sees only their own Discovery
systems. Administrators can sign in from other computers and review requests.
Do not disable certificate checks or browser local-network security.

Linux x64: extract the Linux archive and run ./install.sh as your desktop user
(not root). It opens the same code-free account request without Git or a project. A working
user systemd manager and cgroup v2 are required. Desktop notifications are not
offered by this Linux setup. ./install.sh --project keeps explicit project setup.
The per-user application menu includes DevSetu Connection Status.
Android: install/open the APK, enter your own account, choose health consent and
Request access. Approval connects this device automatically. Android may require
its notification permission before foreground monitoring starts. Its app and
ongoing notification show Connected only after a fresh successful sync.

Using a public HTTPS entry with an already paired computer:
   Download the current installer from your trusted DevSetu entry. Open Setup.cmd
   (or ./install.sh on Linux), choose Advanced update, and change the server URL
   to the complete public HTTPS address, including the entry path. Leave the code
   empty. The selected endpoint must recognize the same device credential and
   owner before its protected address changes. The existing pairing, software
   permissions, monitoring history and runtime identity are retained; no new
   administrator approval is created. A protected previous-address backup is kept.
   A blank new install has no built-in project or private-server URL. A saved
   private URL remains visible until you explicitly verify the replacement.

   On Android, install the APK update over the existing app. Use Change server
   address - keep pairing, enter the complete public HTTPS URL, and Verify and
   save. Do not uninstall or clear app storage. Existing installation identity,
   monitoring consent and device credential stay intact.

Public API access:
   On a configured running service choose API request / response in DevSetu.
   This forwards a bounded request once and displays the response as text/JSON.
   It does not execute remote HTML, forward portal cookies or expose an arbitrary
   target URL. Full application browsing retains its separate preview origin.
