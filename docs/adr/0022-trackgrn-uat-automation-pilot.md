# ADR 0022: Authorize a bounded TrackGRN UAT automation pilot

- Status: Accepted
- Date: 2026-08-23

## Context

The product owner needs FrevOS to manage the operational TrackGRN workspace at
`D:\TrackGRN`. It contains a React UI, ASP.NET Core API, SQL Server migrations,
Playwright tests, and a Windows IIS deployment target. Hosted FrevOS cannot
directly access this laptop checkout. The owner prioritized this project flow
over further Phase 4 UI polish and postponed backup and recovery work.

The generic platform capabilities remain assigned to roadmap Phases 5 through
11. Unrestricted repository or remote command execution for one pilot would
violate the accepted controlled-tool and Windows-agent boundaries.

## Decision

FrevOS will provide one bounded, non-Production TrackGRN pilot without claiming
completion of Phases 5 through 11.

The pilot is fixed to:

- workspace `ws_uat_demo` and project `prj_uat_trackgrn`;
- GitHub repository numeric ID `1334902237`, owner `mishrarishav`, repository
  `TraceGRN`, and default branch `main`;
- Windows companion identity `svc_trackgrn_windows_agent`;
- laptop checkout `D:\TrackGRN` with the exact approved origin URL;
- UAT origin `https://tserver2.eeslindia.org`, API path `/apiTrackGrn`, health
  path `/apiTrackGrn/health/live`, and IIS release root
  `D:\TrackGRN-UAT\releases`.

The control plane persists workspace-scoped operations and exposes only these
business actions:

- `repository.inspect`;
- `repository.propose-commit`;
- `repository.commit-push`;
- `project.build`;
- `uat.deploy`.

The companion polls outward over HTTPS and authenticates with a distinct
runtime token. FrevOS retains only its digest in application memory. The
companion accepts no repository path, server path, host, command, executable,
or script block from an operation payload.

Commit proposals are deterministic file summaries in this pilot. A human may
edit the message. Commit execution requires the reviewed HEAD SHA and change
digest to still match, creates a dedicated `frevos/trackgrn-*` branch, and
pushes only that branch. It never pushes `main` or merges a pull request.
The personal UAT pilot verifies the existing local GitHub CLI operator as
`mishrarishav` and re-resolves provider repository ID `1334902237` immediately
before push. This is not the generic GitHub App credential model required for
multi-project onboarding.

Build executes the checked-in UI build, non-destructive .NET tests, and API
publish. The existing SQL end-to-end fixture creates and deletes an isolated
developer database and is never redirected to the live UAT database. UAT deploy
requires a clean checkout and reviewed source SHA, performs VPN/WinRM preflight,
builds an immutable local artifact, copies it to a SHA-addressed server release,
runs only the checked-in IIS script, and records artifact, service-health, and
database-connectivity evidence.

## Consequences

- The owner can operate the real TrackGRN workflow from FrevOS while preserving
  deterministic authorization and repository governance.
- The laptop companion and configured VPN route are required for deployment.
- A distinct token must be provisioned to hosted FrevOS and ignored laptop
  `server.env`; it is never committed.
- Failed claimed side-effect jobs are not automatically retried.
- Generic onboarding, GitHub App webhooks, model routing, Production promotion,
  rollback, backup, recovery, and arbitrary Windows automation remain absent.
- The pilot does not close Phase 4 or declare Phases 5 through 11 complete.
- Local operator GitHub authentication is a personal-UAT limitation; Phase 5
  still requires the accepted GitHub App installation identity and short-lived
  installation credential model.

## Rejected alternatives

- Giving the control plane WinRM or unrestricted PowerShell authority.
- Accepting paths or commands generated by a model or browser.
- Reusing database, administrator, or WinRM credentials as the agent token.
- Pushing `main` or self-merging a pull request.
- Sending repository changes to Gemini before model/data policy is accepted.
- Treating the UAT pilot artifact flow as Production promotion evidence.
