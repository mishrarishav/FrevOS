# ADR 0062: Configure read-only agents and evidence-based project monitoring

Status: Accepted for the owner's explicit follow-up and goal, 2026-10-26.

This bounded pilot stacks on published source
`1f22ed2a6523678adcff35d8e8d1b9507ddce517`, branch
`codex/agentic-monitoring-pilot`. The preceding configured deployment must pass

The owner explicitly requests this pilot across roadmap areas 6, 7 and 12;
general Phase 4 exit and those full phases are not declared complete.

## Approved experience and data

Add bounded actual CPU/RAM sample graphs with timestamps, offline gaps and no
synthetic utilization. Existing connectors can provide these health samples.
The owner's nine WhatsApp screenshots dated 2026-10-20 are visual references
for configurable agent cards, a network of reporting relationships, status and
activity. They do not prescribe fixed names, role counts, providers or layouts.
Retain the existing workspace navigation/design and responsive accessibility.

Add protected model connection configuration: endpoint, model, authentication
scheme, Test connection and truthful availability. The owner supplies a test
endpoint/credential through a private execution boundary; neither value becomes
a source conditional/default credential. No provider SDK types in domain models.
Credentials are sealed in transit at the application boundary and encrypted at
rest behind opaque references; they are never returned in list/get, audit, model
context or logs. Bind preparation/approval/commit to actor, workspace, target,
digest, nonce, expiry, revision and one use. Deny redirects, unsafe endpoints,
DNS rebinding and missing audit persistence. Connectivity tests send only a
small synthetic prompt. Actual provider availability must be observed.

Each agent has configurable identity, role, parent relationship, model binding,
skills, separately versioned memory.md and enforced guardrails. Memory is
attributed evidence, not authority. Preserve provenance/revisions; never let
retrieved text/provider output change scope, tools, approvals or destinations.
The first runnable pilot supports bounded, explicitly requested read-only
analysis. No model shell, process control, Git, deployment, database writes,
mail, invitations or autonomous disciplinary actions are authorized.

## Project reports and notifications

Use verified workspace project/device/repository bindings and accepted project
plans. Matching folder names are candidates only. Show assigned responsibility
separately from actual OS audit attribution. Show source freshness/gaps.
Completion and schedule variance are deterministic calculations from accepted
weighted milestones, due dates and authoritative plans. File counts, CPU use,
editor activity and a model's guess cannot become a completion percentage or
proof of a person's productivity. Missing plans/bindings remain explicit.

An agent may draft suggestions and local laptop notifications. A human must
review and approve the exact message/device with a single-use, expiring,
actor/workspace/action/target/correlation/digest-bound approval before delivery.
The recipient must locally opt in. Default is draft-only; recheck ownership,
consent and authorization at execution. Bound content/rates/storage and never
interpret a notification as executable instructions. Delivery is not proof
the recipient saw/read it. No real employee message is sent by acceptance tests.

## Validation and deployment

Validate cross-workspace/actor denial, secrets/nonce/revision/expiry/replay,
egress boundaries, actual provider normalization, guardrail enforcement,
truthful project math, graph gaps, local notification consent and approval,
native packaging, browser states and the actual configured DevSetu deployment.
Use synthetic context for endpoint tests; no customer content is disclosed by
default. Preserve all applications, data, uploads, environments and Production
exclusions. Record actual unavailable targets rather than simulating success.
